# 指针坐标到底从哪边算（探针实测 + 成片像素核对）

日期：2026-10-04。目的：确认 `xPx` / `yPx` 的 y 轴原点，以及在成片里画出来的
位置是否与记录一致。这是个「错了会让指针上下颠倒」的问题，但两边都自洽时
看代码是看不出来的，所以用两种独立的办法量。

## 背景

链路上有两个地方各自约定 y 轴：

1. `PointerEventRecorder` 用 `CGEventGetLocation`（Quartz，**左上**原点）
   减去显示器包围盒原点，再按 `pixelSize / boundsPoints` 换算成像素。
2. `ProjectCompositor::composeFrame` 把 `cursor.y` 当成「从内容顶部算的像素」。

两边都按左上原点就没问题，都按左下也自洽（只是画面上下颠倒），
**混合**才会错。所以要分别验证。

## 探针一：两个 API 的原点关系

```
时刻   AppKit(左下原点)      Quartz(左上原点)     和
0      (1286.5, 885.1)      (1286.5, 164.9)     1050.0 (屏高 1050.0)
```

两者 y 之和恒等于屏幕高度（1050 pt），确认 `CGEventGetLocation` 是左上原点、
`[NSEvent mouseLocation]` 是左下原点。事件记录器用的是前者。

## 探针二：真实录制事件的 y 分布

工程 `Jianku Screen 2026-10-03 22-46-50-891`，来源包围盒 1680×1050 pt、
像素 3360×2100，所以 y 的可能范围是 0..2100。

实测 1558 条事件里 `yPx` 落在 79.5 .. 2100，`globalY` 落在 39.7 .. 1050。
若原点在左上，指针在屏幕上半部工作时 `yPx` 应偏小——正是如此。

## 核对：成片里指针的实际位置

最直接的验证是「把带指针与不带指针的同参数成片逐像素相减」，直接量出指针被
画到了哪里，再和记录的位置比。为此在 60 秒处取样——那一段光标静止
（`xPx=1680, yPx=322`），且**不在任何缩放区间内**，相机不会平移画面。

工程的留白 4.5%，画布 3360×2100，所以内容区从 94.5 px 开始，
预期指针左上角为：

| 约定 | 预期 x | 预期 y |
|---|---|---|
| `yPx` 从**顶部**算 | ≈1680 | ≈388 |
| `yPx` 从**底部**算 | ≈1680 | ≈1712 |

**实测差分包围盒**：`x 1678..1741  y 391..493`，共 2765 个像素。

指针左上角 (1678, 391) 对预期 (1680, 388)：相符。结论是
**`yPx` 从顶部算，合成器也按顶部算，链路一致，没有上下颠倒**。

（包围盒高 103 px 而指针本身没有这么高，是因为该光标形状的热点在左上，
图画在位置点的右下方，与代码里 `hotspotX/hotspotY` 的处理一致。）

## 一次假警报，记录在此以免重复踩

一开始在 **40 秒**处取同样的样，量出指针中心在 y≈790，看着像差了一半。
原因不是坐标，而是 40 秒正好落在缩放区间 `37175..39990 ms` 结束之后一点点，
**相机弹簧还在回位**，画面整体在动，所以指针位置也被带偏了。

换到 60 秒（无缩放）后立刻对上。这提醒的是：核对相机相关的像素时，
取样点必须避开缩放区间的过渡段，否则量到的是相机运动而不是被测的那件事。
