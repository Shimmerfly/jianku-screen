## 1. 官网实时指针：确切参数

以下来自官网公开前端资源，不是网络上其他开发者的猜测。用代码中的预设映射关联名称与参数，避免误取页面上其他动画的弹簧。

| 档位 | stiffness 刚度 | damping 阻尼 | mass 质量 | 预设导出标识 |
|---|---:|---:|---:|---|
| Rapid | 530 | 40 | 1 | kH |
| Quick | 340 | 60 | 3 | rh |
| Default | 470 | 70 | 3 | _m |
| Slow | 170 | 50 | 3 | Rw |

证据路径：

- [预设与底层弹簧](https://screen.studio/_next/static/chunks/9764-19903045e53be0b5.js)：模块 27647 定义四组参数；38956 定义 NumberSpring；60287 定义基础配置；395 驱动逐帧更新。
- [名称映射和初始状态](https://screen.studio/_next/static/chunks/1808.2748c8ef4d4c762a.js)：模块 51808 包含档位标签与上述标识的对应关系，初始 movementSpringConfig 为 _m。
- [指针演示行为](https://screen.studio/_next/static/chunks/9717.fb42d71fb105f950.js)：模块 19717 包含鼠标监听、位置与旋转表达式等。
- [样式弹簧封装](https://screen.studio/_next/static/chunks/1232-4168ed5107832875.js)：模块 78889 管理每个属性的独立弹簧实例。

Default 的连续二阶模型可以表述为：

`3 × x'' + 70 × x' + 470 × (x − target) = 0`

X、Y 分别求解，目标持续随鼠标变化。此表达式解释参数含义，并不自动等价于网站的离散数值结果。

### 真实实现中影响手感的细节

- 积分先更新速度，再用新速度更新位置，属于半隐式 Euler 形式。不是直接调用 CSS ease-in-out。
- 底层把时间增量拆为约 1 ms 小步；实际代码的非整数尾步写作 `ceil(dt) - dt` 这一方向的差值，不能在声称精确复现时不经验证就替换成常规余数。该行为需要专门做对照。
- 每次改变目标保留速度，重新计算收敛精度；基础 `precision = 0.002`，实际阈值随当前位置与新目标的距离变化；`clamp = false`。
- 帧驱动使用连续帧时间差；还有估算 settleTime、长时间跨度直接归位等边界。不同刷新率及浏览器调度可能改变像素级结果。
- 指针水平速度参与旋转：角度由 `vx / 240` 计算，并限制在 −20° 到 +20°。不是朝移动方向直接硬转。
- 按下时相对大小变为 0.8，松开回到 1；静止隐藏时目标大小为 0.6，并同时淡出。它们使用另一组弹簧：350 / 40 / 1。
- 初始化 cursorSize = 3；切换“大小”示例或“指针类型”示例时会设置为 5。因此截图选项所在示例会影响大小，不能只读取初始值。
- 静止隐藏参数初始化为 500 ms，仅在相应示例模式启用。源代码相应响应读取横坐标，纯纵向移动是否重置计时应额外验证，不能把演示边界行为误写成理想实现。
- 类型演示在 pointer、pointinghand、ibeamstroke、openhand 间每秒切换。这是演示循环，不能证明网页识别了系统任意光标类型。
- 指针类型图片过渡为 0.2 s，`cubic-bezier(0.44, 0.22, 0.26, 0.99)`；这条曲线属于类型视觉过渡，**不是鼠标位移，也不是镜头缩放曲线**。
- 演示指针有 (140, 60) 的展示偏移，另有滚动速度引入的位置偏移与各指针热点。把展示偏移原样用于实际点击位置会造成错误，必须区分运动模型和演示布局。
- 当前演示代码里的循环是在特定模式空闲后回到保存位置，并非持续直播需要默认采用的功能。

这份证据足以确定网页运动不是普通固定时长缓动，但未证明桌面导出使用同一算法、同一参数或同一时间轴。

## 2. 桌面录屏：什么时候放大、什么时候缩小

官方 [Adding & Editing Zooms](https://screen.studio/guide/adding-editing-zooms) 说明自动创建的缩放基于点击，缩放块有起止边界，可改时长和倍率。[Auto Zoom](https://screen.studio/guide/auto-zoom) 进一步说明聚焦发生点击的区域；无点击的片段需要手动选区域。

因此“所有鼠标移动都触发自动放大”没有依据。静态路径补充了工程初稿的时间规则，但空间聚合、实际镜头时序、焦点偏移与边界限制仍未知。

后续从官方 3.7.5 主进程静态路径定位到**创建工程初稿**的点击区间规则：候选区间约为点击前 300 ms 至点击后 2500 ms，接近结尾的点击会过滤，区间间有合并容差。它不是导出画面的实际镜头时序或完整自动焦点规则；具体数值、边界和证据见[单独记录](官方3.7.5自动焦点初稿.md)。

[Animations](https://screen.studio/guide/animations) 区分指针、镜头缩放与镜头移动的运动模糊；镜头风格有 Focused 与 Smooth。官网文字没有给出物理参数；本轮另从官方 3.7.5 安装包静态定位到预设映射，但网页指针演示仍不能代替桌面镜头行为验证。

[Cursor](https://screen.studio/guide/cursor) 涵盖光标类型、旋转、静止隐藏、去抖等设置。这说明“自然感”包含轨迹处理与渲染组合，不是某一条曲线的单一结果。[Disable smooth mouse movement](https://screen.studio/guide/disable-smooth-mouse-movement) 特别提及菜单场景；后续应重点测菜单选择与平滑指针是否错位。

[Background](https://screen.studio/guide/background) 可以确认 padding、rounded corners、inset、shadow 的设置含义，但不提供所有出厂数值。Background blur 仍保留为用户产品需求，不能将未核实的默认值填入。

同一包中有按录制类型构造设置的函数：窗口／区域或外接设备模式为真时，背景留白比例和圆角取基础值 10、12；两者均为假时，两项为 0。因此不能把“默认留白 10”写成适用整个显示器录制的通则。[官方新录制设置指南](https://screen.studio/guide/managing-project-settings-for-new-recordings)还说明可沿用上个工程设置；3.7.5 的设置界面进一步说明被标为默认的预设会优先使用。实际项目值需要新工程核对。

官方资源的渲染路径把动态模糊强度按 `fps / 60` 换算，指针仅给位移模糊通道，画面平移与缩放分别取各自强度；相邻帧的样式和边界参与滤镜选择。进一步的滤镜分支见[画布与运动模糊](画布与运动模糊.md)。这些静态调用链不足以证明导出时的逐像素结果、实际帧率及预览模式下的开关状态。

## 5. 实时与后期：真正的技术边界

**可以实时平滑**：网站证据已经给出一个只依赖当前与历史输入的实例。主屏继续显示真实指针，观众端绘制平滑指针，技术上无需拖慢实际操作。

**不能由此推导所有后期效果都能无延迟复现**：若后期轨迹消抖、点击吸附或镜头提前进入使用未来数据，实时算法在事件发生前不知道未来。有限缓冲可能帮助，但需要测出依赖窗口，不能保证适用于整个片段的全局优化。

尤其要测点击因果一致性：真实点击使按钮立刻变化，而观众指针可能还在途中。可能的研究路线是同步缓冲画面与事件，再求符合点击时刻的轨迹；只延迟鼠标或只延迟视频都可能制造新错位。此处是待验证方案，不是已知 Screen Studio 内部实现。

若观众视频缓冲而会议语音直接实时传送，还会出现音画不同步。双模式产品已将录制音轨纳入核心范围；演示音频仍须单独处理与会议链路的同步。

## 6. macOS 输出路线

拟议链路：来源屏幕／窗口 → 不带系统光标的捕获 → 对齐时间戳的鼠标与操作事件 → 镜头与指针状态 → GPU 合成 → 观众窗口／副屏。

Apple 的 [Meet ScreenCaptureKit](https://developer.apple.com/videos/play/wwdc2022/10156/) 和 [Take ScreenCaptureKit to the next level](https://developer.apple.com/videos/play/wwdc2022/10155/) 支持屏幕／窗口捕获、排除本应用窗口、控制光标捕获等能力。[SCStreamConfiguration.showsCursor](https://developer.apple.com/documentation/screencapturekit/scstreamconfiguration/showscursor) 对应捕获配置。这里是能力证据，不是本项目已验证的性能保证。

初轮研究考虑过 Swift / AppKit 原生方案；当前按跨平台及成熟实现优先的要求，推荐 Qt + C++ 核心、ScreenCaptureKit + Metal 原生媒体接入，详见技术栈决策。输入权限、真实指针形状、自定义光标、Retina 坐标与不同屏幕缩放比需要另测，不能假设一个系统 API 自动解决全部问题。

| 输出方式 | 对用户的表现 | 本轮判断 |
|---|---|---|
| 副屏无边框窗口 | 观众直接看外接屏幕 | 满足物理输出方向，需扩展桌面及防递归 |
| 独立普通共享窗口 | 会议软件中选择它 | 首选验证，关注遮挡与最小化以及对主屏空间的占用 |
| 系统虚拟显示器 | 共享列表出现另一块显示器 | 备用研究；本轮尚未确认合适的公开、可分发实现 |
| 虚拟摄像头 | 摄像头列表出现一个视频设备 | 与共享屏幕语义不同，不代替核心需求 |

[Zoom 屏幕共享文档](https://support.zoom.com/hc/en/article?id=zm_kb&sysparm_article=KB0060596) 支持指定应用窗口。[腾讯会议共享指南](https://meeting.tencent.com/support/topic/1495/index.html) 支持窗口选择，其 [历史官方 PDF](https://cdn.meeting.tencent.com/upload/website/support-center/meeting-63ec334c202df.pdf) 明确提示最小化／遮挡可能暂停共享。故“隐藏窗口照样能共享”不应作为未测试的承诺。需要在当前版本和接收端实测。
