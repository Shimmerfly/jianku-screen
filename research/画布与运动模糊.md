# 画布适配与运动模糊研究

更新：2026-10-01｜简库镜传内部研究。参考产品名称仅用于技术溯源，不用于功能宣传。静态资料结论与本产品设计建议分别标明。

## 1. 背景铺满与屏幕画面完整容纳

用户要求的效果是：输出分辨率和比例属于观众屏，背景图覆盖整个输出，来源屏幕作为前景按比例摆放。这能用背景取代因比例不匹配产生的纯色边带，不需要拉伸桌面。

Mac 没有统一的屏幕比例。例如 Apple 的比较资料包含 2560×1600 和 3024×1964；前者为 16:10，后者并不是精确 16:10。实际还存在窗口、区域、逻辑点、Retina 像素和可用内容区域的区别；布局必须读取实际捕获宽高，不能按机器类别硬编码。[Apple 规格比较](https://www.apple.com/mac/compare/?modelList=MacBook-Air-Retina%2CMacBook-Air-M1%2CMacBookPro-13-M1)

参考官方 [Background](https://screen.studio/guide/background) 描述了背景、留白、圆角、内框和阴影；[Aspect ratio](https://screen.studio/guide/aspect-ratio) 将成片比例和来源比例分开，并明确“始终保持放大”会裁切来源。由此可确定完整容纳与裁切是不同选项，不能把裁切填满当成无黑边的唯一方法。

以下公式是本产品拟采用的明确定义，**不是已逆向确认的参考软件内部公式或 Padding 单位**。

设输出画布 W×H、来源 S_w×S_h、背景图片 B_w×B_h、最低外留白 p：

- 背景 cover 比例：`k_b = max(W / B_w, H / B_h)`；背景等比缩放后中心裁切，铺满 W×H。允许用户改背景裁切焦点。
- 内容可用框：`A_w = W − 2p`，`A_h = H − 2p`；必须校验为正。
- 无内框时来源 contain 比例：`k_s = min(A_w / S_w, A_h / S_h)`。
- 内容尺寸：`C_w = k_s × S_w`，`C_h = k_s × S_h`；默认在输出内居中。
- 有 inset 时先从可用框扣除四侧内框厚度，contain 来源，再加回内框得到外框尺寸，整体居中。圆角与阴影使用外框，来源裁切使用内视口；必须处理圆角内外半径与透明边缘。

Padding 的 UI 建议按输出短边百分比表达，并把语义／单位写入工程；具体出厂值待参考校准。以下用像素举例方便检查，不表示预设值：

| 来源 → 输出 | 外留白 p | 来源显示尺寸 | 四周剩余区域 |
|---|---:|---:|---|
| 2560×1600 → 1920×1080 | 0 | 1728×1080 | 左右各 96，由背景填充 |
| 2560×1600 → 1920×1080 | 54 | 1555.2×972 | 左右各 182.4、上下各 54，由背景填充 |
| 1920×1080 → 1080×1920 | 54 | 972×546.75 | 上下留下较多背景，这是完整容纳的结果 |

非整数尺寸由渲染器统一亚像素处理，不能每帧不同方向取整造成抖动。背景铺满不要求来源铺满；Padding=0 也不承诺不同宽高比下没有背景。

底层合成顺序建议为：输出背景 → 背景模糊 → 阴影／外框／inset → 裁切后的来源画面 → 与来源一致变换的指针 → 其他叠加元素。运动模糊要考虑各层遮挡和边界，不把静态背景也随镜头拖出残影。

副屏画布始终匹配副屏当前宽高比；会议输出窗口内的固定画布比例与窗口外框分开，窗口缩放仅缩放预览；录像输出由项目导出比例决定。超宽屏、竖屏、窗口源也应用同一规则。

## 2. 运动模糊得到官方确认

参考官方 [Animations](https://screen.studio/guide/animations) 分别提供指针、镜头缩放和镜头移动的运动模糊控制。已把页面和两张配置截图保存在 `evidence/2026-09-30-round2/`。

截图中各滑块位置并不完全相同，且没有精确数字和版本标识。不能按截图估计百分比并宣布是出厂默认；同样，静态配置对象的数值不一定等于截图所示状态。

[Performance Settings](https://screen.studio/guide/performance-settings) 明确说明高质量预览包含运动模糊，性能预览会禁用某些效果。这可以确认模糊参与成片观感并存在成本，不能据此保证参考产品本身在任意低配都全效果实时运行。

自然感至少包含：准确的运动轨迹、连续的速度变化、稳定帧间隔、适当动态模糊，以及镜头停稳后文字恢复清晰。模糊能减轻离散帧的跳跃感，不能弥补错误的轨迹、掉帧或点击错位。

## 3. 官方桌面静态参数及其边界

旧的用户安装包中找到过基础配置候选。本轮又从[官方分发的 3.7.5-4595 安装包](evidence/2026-09-30-official-3.7.5/manifest.json)独立定位到同组基础数值及动画选择器映射，来源疑点已消除；虽已启动应用观察设置界面，仍未建立受控新工程，以下不能自动等同于每个新工程最终生效的设置。

| 字段 | 静态基础值 | 解释边界 |
|---|---|---|
| mouseMovementSpring | 470 / 70 / 3 | 刚度／阻尼／质量；对应桌面光标 Smooth，数值与网页 Default 相同，不能因此认定全部轨迹管线相同 |
| screenMovementSpring | 200 / 40 / 2.25 | 对应桌面画面 Focused；不能直接认为缩放、平移、反向各通道均使用同一个求解过程 |

| motionBlurAmount | 1 | 全局强度乘子，不是 1 像素或 1 毫秒 |
| motionBlurCursorAmount | 1 | 指针子项强度 |
| motionBlurScreenMoveAmount | 1 | 平移子项强度 |
| motionBlurScreenZoomAmount | 1 | 缩放子项强度 |

| cursorSize | 1.5 | 桌面基础值，区别于网页展示大小 3 |

桌面选择器另有光标 Medium 340 / 60 / 3、Rapid 530 / 40 / 1，以及关闭平滑的 None；画面 Smooth 为 170 / 50 / 3。基础对象中的留白 10、圆角 12 在所查设置函数里会按录制对象改为 0；官网还允许沿用上个工程设置作为新录制默认。因此只找基础对象不足以宣布“默认设置已全部核实”。官方值见[结构化参数](parameters/桌面参数-官方3.7.5静态.json)；[旧候选](parameters/桌面参数候选-未验证.json)只保留历史对照。

官方包中的渲染调用链可进一步确认：

- 模糊配置先按 `fps / 60` 缩放；指针使用全局强度乘指针强度，画面平移／缩放使用全局强度乘相应分项强度。这里的 `fps` 来自该渲染路径，是否等于每次导出的最终有效帧率尚未实测。
- 该路径取当前帧及前一帧的样式／边界快照。位移滤镜接收两帧位置差，调用时请求的 kernel size 为 21；缩放滤镜由两帧尺度变化及中心构造，最大 kernel size 为 13。
- 所查选择器比较两帧缩放变化与位置变化，选占优的位移或缩放滤镜；小于其阈值时可能不施加滤镜。**这里并非把两个滤镜无条件叠加**。同时移动与缩放的具体像素结果、渲染层级和边缘处理仍需输出帧核对。
- 2026-10-01 进一步定位父层运动扣除、位移滤镜的单侧等权采样和缩放滤镜的伪随机采样偏移／二次权重。采样与透明边缘的静态结论见[桌面动画处理链第 6 节](桌面动画处理链-官方3.7.5静态.md#6-相邻帧模糊与采样细节)；尚无 GPU 输出或预览／导出一致性验证。

这证明用户观察到的轻微动态拖影有独立的渲染实现依据，明显区别于背景的静态模糊；还不能宣布“全部动态模糊算法已精确还原”。现在可以结合 shader 推导所查分支的取样规则，但仅凭滤镜请求的 kernel size 仍无法确定整个输出帧的最终采样与视觉结果。[官方动画指南](https://screen.studio/guide/animations) 与[性能设置指南](https://screen.studio/guide/performance-settings)分别描述了分项强度及质量预览开启、性能预览关闭部分效果；验证时必须记录预览档位。

## 4. 拟采用的成熟实现方向

先验证参考实际滤镜与参数映射，再选对应 GPU 实现。动态模糊的成熟方向包括按运动向量采样和对多个子时刻累积；不先自研一套复杂时域系统。

- 指针：按实际运动方向、速度与形状采样，处理热点、旋转和透明边缘；可以只处理指针覆盖区域。
- 镜头平移：根据视口变换推导运动向量，避免整帧统一高斯模糊。
- 镜头缩放：不同位置的运动方向和幅度不同，需根据缩放中心和倍率变化得到局部运动，而非使用一个固定方向。
- 缩放和平移同时存在：先按官方 3.7.5 静态路径中的主导变化分支校准；如实际样本显示其他路径，再按逐帧结果修正，不预设无条件叠加两层模糊。
- 背景与文本：背景静止时不参与镜头模糊；镜头停止时不残留拖影。字幕等固定输出元素应有独立运动定义。

[NVIDIA GPU Gems 的运动模糊章节](https://developer.nvidia.com/gpugems/gpugems3/part-iv-image-effects/chapter-27-motion-blur-post-processing-effect) 可作为基于速度采样的成熟技术背景，不能用来证明参考软件采用了其中某个具体公式。

跨 Mac／Windows 使用共用的合成规则和着色器生成链。颜色空间、预乘透明度、纹理边界、采样分布都会影响结果；参数相同不代表像素相同。

需要区分“屏幕内容本身变化”和“本软件镜头／指针移动”。只用当前纹理多采样能近似镜头移动，但不自动还原窗口内滚动或视频内容的时间变化。录后处理可以使用素材历史帧；实时处理若要取得未来帧就必须有缓冲。不得把这些差异藏在“动态模糊”一个按钮下。

## 5. 还要测什么

- 同一运动关闭／开启模糊的逐帧对比，区分轨迹变化和渲染模糊。
- 30／60 fps 下拖影长度是否保持同一曝光语义，默认强度是否依赖帧率。
- 急停、急转、缩放中心附近、视口边界和高对比文字的清晰度。
- 主屏文本响应与平滑指针到达时刻；动态模糊不掩盖因果错位。
- 录制导出、编辑预览与演示输出在相同时间和配置下的差异。

本轮只运行桌面参考以观察设置界面，没有完成录制、制作动效原型或执行帧分析。上述静态参数和设计路线不等于已完成复现。
