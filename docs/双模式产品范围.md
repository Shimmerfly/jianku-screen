# 简库镜传 · 双模式与工程模型

更新：2026-10-02｜产品设计与实施范围。文案遵循 [项目目标](项目目标.md) 的独立功能命名要求。

## 工作流

启动进入“录制”或“演示”，两者共用来源选择、外观预设和指针设置。录制结束后进入编辑器；演示设置页提供观众画面预览和输出状态。不能让演示者在讲解中操作密集时间线，也不能让录制模式只有实时烘焙输出而无录后调整能力。

模式切换应先停止当前任务或明确保留录制，不在后台悄悄丢弃工程。所有录制素材默认本地保存，云端分享另行设计。

## 能力矩阵

| 能力 | 录制／编辑模式 | 演示模式 | 产品阶段建议 |
|---|---|---|---|
| 屏幕、窗口、区域 | 捕获原始素材 | 持续获取来源 | 核心 |
| 麦克风／系统音频 | 分轨保存、音量和静音 | 会议原有音频链路先保留；若缓冲画面需验证同步 | 核心；演示音频路由单独验证 |
| 摄像头 | 独立素材，编辑位置与尺寸 | 可选叠加；不默认占用 | 核心扩展 |
| 指针轨迹与点击 | 独立保存，可离线处理和重算 | 因果处理，有限缓冲另设 | 核心 |
| 自动焦点 | 基于完整录制生成可编辑区间 | 基于已发生的操作管理镜头 | 核心 |
| 手动焦点 | 在时间线调整区间与位置 | 快捷键切换放大／全景 | 核心 |
| 背景、padding、内框等 | 随时改，不修改源素材 | 实时调整或切换预设 | 核心 |
| 动态模糊 | 预览与导出，同一效果定义 | 完整演示效果的一部分 | 核心 |
| 裁剪、切分、删除、变速 | 非破坏性时间线 | 不适用进行中的来源 | 核心 |
| 撤销、重做、保存、重开 | 工程编辑 | 设置撤销／恢复预设 | 核心 |
| 视频导出 | MP4 候选首要格式，输出比例／清晰度／帧率 | 非必须；可额外录制 | 核心 |
| 快捷键显示、点击声音、音乐 | 记录事件后可调 | 按实时可用性选配 | 后续对照补齐 |
| 字幕、转写、音频增强 | 可离线处理 | 实时能力单独评估 | 后续对照補齐 |
| 设备录制、设备框 | 受平台接口影响 | 单独评估 | 后续平台能力 |
| 遮罩、高亮、GIF、分享预设 | 编辑／导出扩展 | 可用部分独立设计 | 后续对照补齐 |
| 在线分享链接 | 涉及上传、存储与访问控制 | 不直接属于本地输出 | 独立服务范围 |
| 统一设置与逐项默认值 | 编辑当前工程，每项可单独设为新工程默认 | 演示模式读取同一外观／动画定义 | 核心 |
| 常驻后台与快速截图 | 窗口全关闭时不保留采集／预览 | 菜单栏入口、可配置全局快捷键、套用同一外观参数导出图片 | 核心 |

“后续”是实施排序建议，并非从长期目标删除。核心能力列表也不是已实现清单。

参考官网关于 [原始素材提取](https://screen.studio/guide/extracting-raw-recording-files)、[裁剪](https://screen.studio/guide/trimming)、[变速](https://screen.studio/guide/speeding-up-the-video)、[导出](https://screen.studio/guide/explanation-of-export-settings) 的资料用于确认能力类别；本产品的数据模型为独立设计。

## 工程应保留什么

建议未来的录制工程目录／包内包含版本清单、源媒体、事件、时间线、外观设置和可重建缓存。具体录制工程文件扩展名尚未确定；当前已建立应用工程，录制工程格式尚未实现。

配置分为版本化的参考工厂值、用户逐项默认值、当前使用值三层；录制工程创建时应保存独立快照，保证后来修改默认值不会改动旧工程。快捷截图读取当前使用值。布局和视觉特效由录屏、观众画面与静态截图复用同一参数解释；共享解释器仍待实现，当前只接通部分画布参数。

- 原始屏幕视频：尽可能不烘焙鼠标、背景和镜头变换。系统捕获无法移除的应用自绘光标要识别为兼容性问题。
- 系统音频、麦克风、摄像头：记录各轨起点、时间基准与丢帧信息；可独立重新编辑。
- 事件：鼠标位置、点击按下／松开、滚动、光标样式与热点、来源坐标转换。光标资源需跨平台可用，不能只存系统内存句柄。
- 时间线：片段源区间、目标区间、播放速度、静音／裁切与缩放区间。速度变化后事件、音频和镜头的时间映射要一致。
- 样式：背景、留白、内框、阴影、指针、镜头模型版本、模糊参数与输出比例。
- 缓存：缩略图、波形、代理媒体、分析结果；允许重建，不将缓存当唯一原始素材。

为跨平台保存相对路径、资源 ID 和明确单位；不将 CGPoint、NSScreen、Metal 句柄或 Windows 设备句柄写入工程。硬件对象只存在于运行时适配层。

## 录制与演示的共享方式

捕获后的数据分为三条按需开启的支路：保存原始素材、记录输入事件、实时合成观众画面。结束后使用原始素材和事件生成编辑工程。

同一动画引擎与画布渲染器服务编辑预览、离线导出和实时输出；时间来源与焦点规划器分别配置。录制后的完整分析可以重算焦点，演示中的每帧不能假装知道未来。

若选择同时录制与演示，建议同时保存现场手动缩放操作，以便“保持现场镜头”或“重新生成镜头”。再录一份已合成成片是另一项负载，不作为默认必需。

## 编辑器细节

- 新建项目自动生成可编辑初稿，原始素材保持不变。
- 时间线需要能跳转、拖动区间边缘、拆分、删除、调整倍率与焦点；撤销重做覆盖设置和时间线操作。
- 修改输出比例后重新求布局和镜头边界，保留原始画面，不通过拉伸填满。
- 普通外部视频若没有轨迹，不能承诺还原其原始鼠标；提供手动焦点，自动光标分析另列研究。
- 长录制建议分段可靠写入，自动保存项目与事件；异常恢复、磁盘不足提示属于录制基础能力。
- 预览和离线导出共享规则，导出可慢于实时；预览质量降低应明显标示，不影响最终导出设置。
- 无障碍、键盘操作、时间线缩放和触控板手势属于 Mac 体验验收，不因跨平台而略去。

## 不提前承诺的范围

不承诺读取竞品私有工程格式；不承诺所有视频来源都有可重建鼠标；不承诺 Windows 与 macOS 的平台专属设备能力完全相同；不把未来在线服务计作当前本地能力。

开发顺序建议：素材＋事件＋工程闭环 → 动画和画布对照 → 编辑／导出 → 演示输出与会议验证 → 扩展能力。实际开工后按最关键风险交错验证，演示共享链路不能拖到最后才首次验证。
