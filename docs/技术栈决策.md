# 简库镜传 · 技术栈决策

更新：2026-10-02｜已获开工授权；此处技术选择以 [项目目标](项目目标.md) 的产品与命名约束为准。

## 决策

采用 **C++20 + Qt 6 / Qt Quick（QML）+ GPU 合成 + 原生捕获／编解码适配层**。UI 和编辑核心跨平台共用，Mac 与 Windows 分别接入各自成熟的系统能力。

这项选择以完整动画、Mac 体验、可靠性和未来 Windows 复用为依据。低配优化是附加收益，不以极限内存占用或最老机器兼容为主要目标。不为此维护两套完整界面，也不自研通用图形引擎、编码器或虚拟屏驱动。

## 组件分工

| 层 | 选型 | 复用与边界 |
|---|---|---|
| 控制界面、设置、编辑器 | Qt 6 Quick / QML，C++ 数据模型 | 共用大部分 UI；菜单、快捷键、文件对话框和平台风格分别适配 |
| 动画、焦点、时间线 | C++20 | 同一参数、状态和时间语义；不使用 QML 默认 easing 代替已核实模型 |
| GPU 画布 | Qt RHI、Qt Shader Tools，预览接 QQuickRhiItem | 共用合成逻辑；Mac Metal，Windows 优先 D3D11 |
| Mac 捕获 | ScreenCaptureKit；少量 Swift / Objective-C++ 适配 | 得到帧、音频与时间戳，处理权限和来源选择 |
| Windows 捕获 | Windows.Graphics.Capture，C++/WinRT | 接入 D3D11 帧；系统音频按需接 WASAPI |
| 编解码 | Mac VideoToolbox；Windows Media Foundation 的硬件能力 | 按设备检测，不能把“支持 API”当成“必有对应硬编” |
| 媒体封装与格式处理 | FFmpeg 的必要库 | 优先成熟封装／解封装／重采样，不把每帧实时链路接成 CLI 管道 |
| 工程数据 | 版本化 JSON 清单 + 素材文件 + 独立事件记录 | 跨平台相对路径、时间基准、撤销记录及迁移规则 |
| 用户默认设置 | 版本化、逐项覆盖的用户配置 | 与工程快照分离；每项可设为默认和恢复工厂值，截图与新工程共享默认来源 |
| 后台入口与快捷键 | macOS 菜单栏状态项、系统全局快捷键 | 所有窗口关闭后释放媒体资源；后台截图复用共享画布设置 |
| 构建 | CMake，锁定依赖版本 | 共用核心独立构建；Windows 核心测试应早于完整 Windows 界面交付 |

推荐锁定一条满足支持系统范围的稳定 Qt 6 版本线，在开工验证后定具体版本；不从滚动文档的版本号推断发布和兼容保证。

## 为什么没有选择其他路线

| 路线 | 优点 | 此项目的取舍 |
|---|---|---|
| Qt + C++ + 原生媒体接入 | 桌面跨平台成熟，GPU 与原生纹理有官方接入路径 | 本次推荐；需处理 Qt GPU 接入与 Mac 交互细节 |
| Swift 原生 UI + C++ 核心，Windows 再写 WinUI | Mac 原生交互控制最充分 | 仍可行，但两套 UI 和编辑器维护成本高于当前需要 |
| Electron + React + 原生媒体模块 | 编辑器 UI 生态成熟，参考安装包也包含 Electron | 可做高质量产品，不因低配一票否决；本次选择 Qt 是为了更直接整合共享媒体核心和 GPU 纹理，不是断言 Electron 必然慢 |
| Tauri + Web UI + Rust | 复用系统 WebView，Rust 可用于高性能核心 | 仍需要原生媒体、纹理桥接与跨 WebView 差异验证；包体小并不自动让合成更快 |
| 整体嵌入 libobs | 成熟捕获／合成／编码模块 | 可继续评估，但它不提供本产品的非破坏性编辑器和目标动画；不把采用 OBS UI 或全套引擎当成必需 |

Rust 也能胜任共享核心；这里选 C++ 的主要原因是 Qt、GPU 接入和成熟媒体库的组合便利，不是声称语言本身保证更高性能。

## 使用成熟方案的具体方式

Qt 官方说明其场景图通过 RHI 适配 Metal、D3D 等后端；有 [Metal 纹理导入示例](https://doc.qt.io/qt-6/qtquick-scenegraph-metaltextureimport-example.html)。[QQuickRhiItem](https://doc.qt.io/qt-6/qquickrhiitem.html) 提供自定义 GPU 内容嵌入 Qt Quick 的路径。这些用于复用图形基础设施，不再自建跨平台窗口和渲染抽象。

注意：QQuickRhiItem 是公开接口，但 QRhi 家族只有有限兼容保证，部分接入需链接 GuiPrivate。将这部分封装在小模块并锁定 Qt 版本，升级时做针对性验证。它不支持 Qt 软件渲染后端，因此不承诺无可用 GPU 的机器全效果运行。跨 GPU／跨设备纹理需要明确同步与复制，不能宣传绝对零拷贝。[Qt 接口说明](https://doc.qt.io/qt-6/qquickrhiitem.html)

Mac 的采集样本由 IOSurface 支撑的 CVPixelBuffer 提供，可走 GPU 纹理映射；Windows 捕获提供 D3D11 帧池。优先沿官方实例接入，不用定时截图和 CPU 拼图替代。参考 [Apple 捕获样例](https://developer.apple.com/documentation/screencapturekit/capturing-screen-content-in-macos) 与 [Microsoft 屏幕捕获](https://learn.microsoft.com/en-us/windows/apps/develop/media-authoring-processing/screen-capture)。

编码使用 [VideoToolbox](https://developer.apple.com/documentation/videotoolbox) 或 [Media Foundation 硬件转换能力](https://learn.microsoft.com/en-us/windows/win32/medfound/mf-readwrite-enable-hardware-transforms)。实时演示到本地窗口本身不需要先编码再解码；由会议软件负责它的网络编码。录制、成片导出和本地演示应分开调度。

OBS 是成熟实现的研究入口，特别是来源、音视频时钟、场景合成和输出生命周期；不声称本项目直接继承其性能。其代码采用 GPL v2 或以后版本，FFmpeg 的许可取决于构建组件；采用或分发前按实际选用模块处理许可，当前不默认复制 libobs 或混用来源不明代码。[OBS 官方仓库](https://github.com/obsproject/obs-studio) · [FFmpeg 官方说明](https://ffmpeg.org/legal.html)

## 保住 Mac 体验

Qt 控件并不等于全部原生 AppKit 控件。原生菜单与标准快捷键、Retina 和混合缩放、多屏窗口行为、全屏／Space、权限、文件拖放、触控板时间线操作与音频设备切换，都列入 Mac 验收。Qt 的 [macOS 风格](https://doc.qt.io/qt-6/qtquickcontrols-macos.html) 是起点，不替代交互设计。

视频帧和动画状态在媒体／渲染线程工作；QML 只操作参数、选区、时间线与命令，不承载每帧大图像和高频鼠标事件。避免 UI 滚动或调整设置阻塞音视频线程。

## 共享核心需要提前定好的边界

- 原始素材时间、剪辑后时间、实际播放时钟分别表示，采用整数／有理数时间基准，不用浮点秒不断累加制造漂移。
- 统一事件结构：时间戳、来源 ID、位置、坐标系、鼠标类型与热点、按下／释放／滚动；按显示器缩放和重排记录坐标转换。
- 项目格式记录动画模型版本和参数，不只写一个含义会变化的“默认”字符串。
- 录制模式可离线分析未来轨迹；演示模式只使用因果数据或有界缓冲。规划器不同，动画求值和合成规则尽量共用。
- 导出渲染不能依赖可见预览窗口或显示器刷新时钟；预览与导出用同一渲染逻辑，分别由播放时钟和输出帧时间驱动。
- 多个 Qt 窗口不保证共享同一 GPU 设备／RHI 实例；输出扇出先用框架支持的资源导入／同步方式验证，不能直接传纹理句柄就假设有效。

## 适量性能工作

先用正常机器验收完整效果；再看测量结果决定是否优化。采用硬件编解码、纹理池、静态背景缓存、避免无效重绘和有界队列即可作为第一轮常规工作。硬编与解码需保留软件兜底或明确不支持状态，不能静默卡死。

编辑预览可以提供显式的预览质量设置；导出保持选择的质量，可花更长时间。演示性能不足时提示降低输出分辨率或帧率，不能偷偷关闭动态模糊后仍称“完整效果”。不做未经验证的任意硬件／4K60 保证。

先测建议基线 1080p60；记录帧间隔、端到端延迟、音画同步、内存是否持续增长和 GPU 资源释放。低配档不是阻塞正常版本交付的独立门槛。

## 开工后的最小选型验证

1. Mac 采集纹理 → Qt GPU 合成 → 观众窗口，确认色彩、DPR、光标和资源生命周期。
2. 同一画布离屏渲染 → 硬件编码成片，确认结果与预览一致。
3. Windows 核心编译与 D3D11 纹理导入验证，避免 Mac 完成后才暴露不可移植设计。
4. 动画、动态模糊和会议共享接收端验收。验证发现 Qt 纹理／编码桥接造成明显成本时再局部接原生后端，不预先维护两套引擎。

这些是开工后的验证任务，完成状态以独立开发进度记录为准。
