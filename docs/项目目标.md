版本：0.5｜2026-10-03｜状态：调研与方案阶段。**按用户最新指令：在收到明确的“开工”提示之前，不进入实现。**

## 0. 需求解读（产品经理视角）

用户的原始诉求是口语化、跳跃的。本节把它翻译成结构化产品需求，并补齐用户未明说但实现必需的细节。若解读与用户本意有偏差，以用户为准。

### 0.1 一句话目标

做一款先面向 macOS、架构可延展到 Windows 的录屏产品：**录制成片**与**实时演示输出**两个场景，都要具备参考录屏软件那种「指针平滑、跟随焦点自动/手动缩放、画面包装、轻微动态模糊」的自然观感。动画必须按固定版本 1:1 复刻（含默认参数、曲线、时序、模糊），不允许用「随便一条非线性缓动」搪塞。

### 0.2 用户真正想要的四件事

1. **平滑指针**：录屏里指针不再生硬、抖动、瞬移；带与水平速度相关的轻微旋转；点击有缩放反馈。
2. **焦点缩放**：像参考软件那样围绕操作自动放大、必要时平移、结束回到全景；也能用快捷键手动放大/缩小。真正决定「何时放大、放大多少、缩到哪里」的逻辑要照参考来。
3. **画面包装 + 实时输出**：背景（图/纯色/渐变）铺满、padding、圆角、inset、阴影、背景模糊。这些不仅用于成片，**在实时演示输出里也要能调**。
4. **第二屏/共享输出**：主显器显示内容保持不变，第二个副显示器看到加工后的效果；没有副屏时，提供一个可供会议软件（Zoom、腾讯会议等）选中的输出窗口。

### 0.3 用户已自行澄清或修正的点（以此为准）

- 焦点跟随**不是简单开关**，而是**自动 / 手动 两档切换**（用户明确纠正）。
- 手动档：按一次快捷键 → 副屏放大；再按 → 缩小；再按 → 放大。放大期间画面要平滑跟随。
- 自动档：像参考软件一样跟随光标操作自动放大。需提供「回到全景」。
- 快捷键要可自定义，并能检测冲突、忽略长按重复。
- 用户认可参考软件的**默认参数**手感舒适，所以要的是「默认行为」的复刻，不是自己调一套。
- 用户观察到参考软件放慢时有**轻微动态模糊**，认为这是「丝滑自然」的关键来源，要求一并研究并还原。
- 比例问题：Mac 屏常是 16:10 或接近 16:10，主流副屏常是 16:9；直接镜像会出现左右黑边。用户已提出解法：**以背景图按副屏比例铺满打底，再放主屏镜像画面**（即 padding/contain 思路）。背景图要自适应副屏比例。

### 0.4 实时 vs 后期：必须写进验收的技术边界

- **指针平滑可实时**：参考官网的实时演示直接用「弹簧 + 逐帧数值积分」生成平滑指针，覆盖所有指针选项。因此本项目不需要「后期平滑指针」才自然，实时可行。
- **焦点「何时放大」可实时（因果）**：参考默认依据**点击**（已发生事件）决定进入/维持/退出。
- **焦点「放大后看向哪」参考里依赖未来**：参考对放大区间内的事件做贪心分组、取包围盒中心，而中心**包含组内后续事件**。纯实时无法提前知道未来事件。因此演示模式只能二选一：①接受**有界延迟缓冲**（需实测可接受范围与音画影响），②用因果近似并**逐帧对照记录与录制成片的差异**。这一点不得含糊，也不能把因果近似标成 1:1。
- **动态模糊可实时**：本质是单帧内按运动方向多采样，GPU 有成本但可实时。

### 0.5 两种模式的边界

| | 录制模式 | 演示模式 |
|---|---|---|
| 目的 | 录下素材，事后编辑、导出成片 | 实时把加工后的画面送到副屏/共享窗口 |
| 指针 | 独立记录，可录后重算 | 实时平滑合成 |
| 焦点 | 可用整段未来轨迹离线重算 | 只用已发生事件或有限缓冲 |
| 主屏 | 不受影响 | 不受影响，真实鼠标与响应不变 |
| 输出 | MP4 等成片 | 副屏全屏 / 独立共享窗口 |

### 0.6 用户强调但容易被忽略的点

- **动态模糊**必须还原（按指针 / 平移 / 缩放分项）。
- **文案硬约束**：所有产品文档、功能简介、UI 文案**不得出现竞品名称**，也不得写成「某软件同款」；研究资料里为溯源可标注来源。
- **低配优化**尽力而为，不设为主要架构约束，不为它牺牲关键动效。
- **先文档后开工**：未收到明确开工提示前不进入实现。
- **优先复用成熟实现**（系统捕获、硬件编解码、Qt/GPU、OBS/FFmpeg 等已有途径），不重复造轮子。

### 0.7 用户未明说、但必须补齐的细节

- **权限**：屏幕录制需要系统授权（TCC）；重编译或签名变化可能导致授权失效，必须有清晰的状态与引导。
- **时间基准**：素材、鼠标事件、光标外形必须用统一整数/有理数时间基准对齐，禁止用浮点秒累加制造漂移。
- **素材与事件分离**：录下的画面不带指针（或可关），指针位置/点击/光标外形独立记录，便于录后重算并供实时合成复用。
- **光标外形**：不能只存坐标，要存光标类型 + 热点 + 图片；静止期间换型也要补事件。
- **工程可移植**：版本化 JSON + 相对路径，不写入平台句柄（Metal/D3D/CGPoint 等只存在于运行时）。

## 1. 产品定位与硬性要求

这项验收标准同时适用于录制成片、编辑预览、演示输出与截图中涉及的画面动画和交互反馈。不同模式须核对同一输入条件下的触发、时间曲线、帧间连续性、模糊、边缘及最终构图；界面微动效也应以实测参考为准。未取得逐帧对照证据的动画只能标为待实现或待验证，不能以主观“顺滑”判定完成。

## 2. 两种工作模式

| 模式 | 用户流程 | 结果 |
|---|---|---|
| 录制模式 | 选择屏幕／窗口／区域与音频 → 录制 → 自动生成初稿 → 编辑 → 导出 | 可继续编辑的工程与成片 |
| 演示模式 | 选择来源 → 设置背景与观众输出 → 选择自动／手动焦点 → 开始演示 | 副屏或会议共享窗口中的实时处理画面 |

录制模式要保留原始素材、鼠标轨迹及点击事件。背景、指针、缩放与剪辑均可在录后调整，不只保存一份烘焙好的成片。演示模式只改变观众画面，不改变主屏内容、真实鼠标坐标和输入响应。

演示后如需继续编辑，建议提供“同时保留录制工程”选项；同时捕获、编码和演示的负载需另行测试，不默认强制开启。

## 4. 焦点交互

“何时缩放”与“放大后如何跟随”分开。

- **自动**：依据操作事件决定进入与退出放大，管理放大期间的视野。参考资料确认点击是关键依据；聚合、保持、退出阈值仍需核实，不自行填一个秒数称为默认。
- **手动**：快捷键第一次按下围绕当前光标附近放大，再按缩小；放大期间继续平滑跟随。快捷键可自定义、检查冲突、忽略长按重复。
- **关闭缩放**：保持全景，仍可使用指针平滑和背景包装。

建议提供独立“回到全景”命令。动画中反向操作从当前状态和速度衔接，避免跳回起点。自动转手动时保留当前画面；手动转自动清理旧计时并等待新事件。以上为本产品交互建议，参考行为待对照验证。

自动模式须覆盖阅读停留、快速连续点击、跨区域点击、菜单、拖拽、选择文字、滚动和输入。鼠标停住不立即缩小，放大后不强制永远居中。视野不得越出来源边界。录制模式可使用完整轨迹分析；演示模式只能使用已发生事件或明确配置的有限缓冲，二者的事件规划不冒充完全等价。

## 5. 画布与画面包装

**演示输出画布跟随观众屏的实际宽高比；背景铺满整个画布；来源画面保持自身比例放入内容框；比例差异露出背景，默认不拉伸、不裁掉来源内容。**

不把 Mac 固定视为 16:10，也不把所有副屏固定视为 16:9；用实际捕获尺寸与目标输出尺寸计算。录制成片可另选 16:9、9:16、1:1 或自定义比例。

| 设置 | 定义 |
|---|---|
| 背景 | 图片按 cover 等比铺满目标画布，可裁切背景；也支持纯色和渐变 |
| 背景模糊 | 只处理背景层，静态背景可缓存 |
| Padding | 内容外框到画布边缘的最低留白；比例不同可能使某一方向留白更多 |
| 圆角 | 内容外框边界，不随输出分辨率失去一致性 |
| Inset | 外框内部额外边框／内间距，与 Padding 分开 |
| 阴影 | 内容框对背景的投影 |
| 动态模糊 | 根据运动轨迹作用于指针、镜头平移与缩放，与背景模糊分开 |

Padding 为零不意味着任意宽高比下都没有背景；完整容纳、保持比例、完全占满三者在比例不同时不能同时满足。若用户主动选择裁切填满，必须明确显示裁切范围。

布局规则、例子和动态模糊研究见 [画布与运动模糊](../research/画布与运动模糊.md)。

## 6. 输出可靠性

副屏在扩展桌面下显示独立观众窗口。来源与输出防止递归捕获，控制面板与预览不进入来源画面。镜像模式无法满足两屏显示不同结果，应明确引导，不能悄悄改变系统布局。

无副屏时优先采用名为“简库镜传 — 演示输出”的独立共享窗口。必须在当前腾讯会议和 Zoom 的接收端验证，尤其是被遮挡、最小化、切换 Space、尺寸变化时是否持续输出。若方案要求窗口占用主屏空间，需要明确呈现限制，再研究虚拟显示器。虚拟摄像头属于摄像头来源，不能替代共享屏幕中可选择输出的要求。

拔掉副屏不把全屏输出自动盖到主屏。来源关闭、权限撤回和暂停时显示明确状态／占位画面，不以旧帧伪装仍在直播。

录制要处理长录音画同步、磁盘不足、应用异常退出、素材丢失与工程迁移。剪辑只改变工程描述，不覆盖原始素材。

## 7. 技术选型与性能边界

推荐 **C++20 + Qt 6 / Qt Quick + Qt GPU 渲染接口 + 平台原生捕获和硬件编解码**。Mac 使用 ScreenCaptureKit、Metal、VideoToolbox；Windows 预留 Windows.Graphics.Capture、Direct3D 11、Media Foundation。FFmpeg 用于成熟的媒体封装、格式适配和必要的媒体处理，具体模块按需求选择。

共享动画数学、时间线、工程数据、布局与渲染逻辑；将操作系统权限、屏幕捕获、声音、光标、编码与窗口集成隔离在平台适配层。Qt 不代表捕获和编码自然跨平台，也不保证完全等于原生控件体验，Mac 的菜单、快捷键、Retina、窗口和权限流程必须单独打磨。

先实现正常机器上的完整效果及稳定输出。只做直接有效的常规优化：硬件编解码、GPU 合成、背景缓存、有界队列、避免每帧 CPU 往返拷贝。1080p / 60 fps 是建议测试目标，不是未经测量的性能承诺。低配策略不另起大型研发分支。

详见 [技术栈决策](技术栈决策.md)。

## 8. 动画验收与开工边界

1:1 复现是产品体验的核心要求。验收覆盖完整处理链：轨迹预处理与时间采样；触发时机与焦点选择；位置、速度、缩放、过冲、收敛与反向连续性；指针热点、旋转、点击反馈、隐藏和换型；动态模糊的方向、强度、采样、透明边缘以及构图。任何已发现的细节差异都应进入缺陷清单，继续定位和修正，不以“同样使用非线性动画”“大体相似”或“已找到同组弹簧参数”替代验收。

固定参考版本、默认设置、输入轨迹、采样与输出条件，以逐帧叠加、轨迹差分和视觉对照验证。数学模型一致、有限样本通过与全部行为等价是不同结论。官网指针演示不能代替桌面镜头基准，配置对象不能代替官方版本运行结果。

若后期效果使用未来数据，需明确实时模式的可达边界和所需缓冲；不得静默降低动画要求，也不得保证任意低配在任意分辨率都全效果流畅。低配适配不通过不阻止正常配置版本推进。

当前为方案阶段，未获开工提示前不实现。开工后先验证核心运动、GPU 画布、素材与共享输出链路；统一设置、逐项默认值及后台截图纳入核心工程模型和验收，不等完整编辑界面完成后才设计。

## 10. 现有实现评估与重构方向

### 10.1 现状（2026-10-03 审计）

现有 `Jianku Screen`（Qt6 + QML + ObjC++）已跑通：ScreenCaptureKit 显示器捕获 → IOSurface/Metal 纹理 → Qt Quick 预览；AVAssetWriter H.264 录制；指针事件与光标图片写 JSONL；三级设置存储；菜单栏常驻；Carbon 全局快捷键；快捷截图。

但**产品的全部价值点尚未实现**：

- **无动画引擎**：`automaticZooms` 只离线产出 `[start,end,zoom=2]` 区间，没有任何随时间求值的姿态计算，产出的 `automatic-zooms.json` 无人读取。
- **无合成器**：画面包装在 QML 与 QPainter 各写一份、公式还不一致（padding 一处按画布短边、一处按来源短边），颜色也不同。
- **无指针平滑/旋转/点击反馈**；录制的 MP4 里**完全不含指针**（`showsCursor=NO`），采到的光标图片从未被使用。
- **无动态模糊、阴影、背景模糊**（仅存参数）。
- **无音频、窗口/区域来源、工程编辑、正式导出**。
- 演示模式只是第二个原始视频窗口，未独立输出到副屏，也没有加工画面。
- `MacCapture.mm` 是 688 行 God object，把捕获/编码/工程 I/O/事件编排混在一起。

> 注：`docs/开发进度.md` 的部分描述已与代码不符（如「光标已烘焙进 MP4」「事件采集只是草稿」），应据代码修正，避免误导后续 AI。

### 10.2 重构目标分层（待开工后执行）

```
Capture adapter (SCK / WGC)        ← 平台相关，只产出帧 + 时间戳
        │
Event & Cursor Track model         ← 事件/光标外形/热点，统一时间基准
        │
Animation Engine (纯 C++，无 UI)    ← (媒体时间, 事件, 参数) → FramePose
        │                              （指针位置/旋转/缩放、镜头中心/倍率、模糊权重）
Compositor (GPU / RHI)             ← 背景 + padding + 圆角 + inset + 阴影 + 来源 + 指针 + 运动模糊
        │
Output drivers                     ← 预览 / 副屏 / 共享窗口 / 离线导出（同一引擎与合成器）
```

关键原则：

- **一个引擎、两种驱动**：离线导出按输出帧时间驱动，实时演示按播放时钟驱动；参数与合成规则共用。
- 先把**时钟/时间轴**从 `MacCapture.mm` 抽成版本化模型，消灭散落的 `16666667`、`1/60` 常量与时长补偿。
- 指针必须**独立于视频**：录制排除系统光标，合成时用事件 + 光标资源重绘。
- 录制成片与演示输出都走同一 Composer；演示模式再叠加因果/缓冲策略。
- 先做**最小垂直切片**：捕获 → 事件 → 弹簧指针 → GPU 合成（背景+padding+圆角）→ 副屏窗口，用参考视频逐帧对照。

### 10.3 建议落地顺序（开工后）

1. 抽时钟/时间轴模型；建立事件与光标外形数据模型（读回现有 JSONL）。
2. 实现弹簧求解器（半隐式 Euler、1ms 子步、`ceil(dt)−dt` 尾步、目标变更保速）与指针姿态（位置/旋转/点击/隐藏）。
3. 实现共享布局计算 + GPU 合成器（背景/padding/圆角/inset/阴影）。
4. 实现自动焦点（区间生成 + 分组 + 边缘构图）与手动焦点，录制/演示共用。
5. 运动模糊（分项强度、主导变化、采样）。
6. 副屏输出 / 独立共享窗口 / 会议软件实测。
7. 音频、工程保存、编辑、正式导出。

每一步都以固定参考版本、固定输入轨迹、逐帧叠加/差分验收；未验证的保持「待验证」。
